# 只有参考运行时才看得见的 `#2006`（第十一轮）

用户第三次贴截图：**「adl运行这两个选择都是报错的」** —— `select` / `combobox` / `datePicker`
三页，一点下拉就在控制台刷：

```
RangeError: Error #2006: The supplied index is out of bounds.
    at flash.display::DisplayObjectContainer/setChildIndex()
    at asaot.ui::Reconciler/fixDisplayOrder()
    at asaot.ui::Reconciler/reconcileChildren()
    …
    at asaot.ui::UiApp/onEnterFrame()
```

页面**停在上一棵树**（reconcile 在那一帧被打断，后续节点从未排好序）。同一份源码在我们自己的
AOT 上跑：41 页全绿、像素逐字节相同、41 道门没有一个变红。

这是前两轮那个病根的**第三个、也是最纯粹的一个实例**：**我们的运行时比 AIR 宽容**，于是库的错误
在我们这边可以无声通过。前两例（`toast` 的 `tone: "info"`、`onChange()` 少传参）至少两边都抛，
只是被帧守卫接住、只有「真点一下」才看得见；这一例**只有 AIR 抛**。

---

## 1 根因：两层，缺一不可

### 1.1 库侧：显示位用「描述下标」算

`Reconciler.fixDisplayOrder` 负责把 author 描述的兄弟顺序翻译成 display list 顺序。原来的写法是

```as3
n.backing.setChildIndex(c.backing, n.internalCount + i);   // i = 描述下标
```

`internalCount` 是 `build()` 造出的自有子件数（背景/边框/标题…），内容子件排在它们之后——对扁平
情况完全正确。**但弹出的下拉会把属主 `lifted` 出去**（§3.3 第 19 条：为了越过后续兄弟的 z 序，属主的
`backing` 被 reparent 到 `app.stageContainer`）。被抬起的节点**仍占描述树的一个槽位，却已不在父
backing 里** ⇒ 之后每一个兄弟的 `internalCount + i` 都多算一。`index == numChildren` 就是越界。

打开 `select` 的下拉，恰好就制造了这个状态：`slot = internalCount + <本地下标>`，被抬起的 owner 已经
腾空了一个槽位，而计数没减。

### 1.2 编译器侧：越界索引被**夹紧**，而不是抛错

`as3compiler/src/emit.ts:11635` 生成的 `DisplayObjectContainer_setChildIndex`：

```c
if (cur < 0) return;                                        // 不是我的孩子 -> 静默返回
if (index < 0) index = 0;                                    // 夹紧
if (index >= c->children->length) index = c->children->length - 1;   // 夹紧
```

AIR 的语义是：越界 → `RangeError #2006`；不是孩子 → `ArgumentError #2025`。**我们两边都静默放行**
（`getChildIndex` 的 `#2025` 早已对齐，`setChildIndex` 没有）。已登记为缺口 **G24**
（[`../compiler-gaps.md`](../compiler-gaps.md)）。

**为什么这条决定了「AOT 永远发现不了」**：夹紧后的位置 `numChildren-1` 恰好就是最后一个孩子的
正确落点 —— 显示序**完全正确**，像素一模一样。所以：

- 41 页截图扫描（只渲染）→ 绿；
- 19 个 AOT 探针（含 overlay/popup/flip/choice 的显示序断言）→ 绿；
- 41 道门 → 绿。

它们测的都是「画面对不对」，而这一次画面是对的。**AIR 报的不是画面，是我们交给它的一个非法索引。**

## 2 复现：让 AIR 自己把话说出来

AIR 不能被脚本点击（`adl` 的窗口由操作系统驱动），而且 `mxmlc` **拒收** `NativeApplication.argv`
（实测 SDK 51.4.1：*「通过静态类型为 `NativeApplication` 的引用来访问的属性 `argv` 可能未定义」*）。
所以复现夹具长这样：

| 环节 | 做法 | 踩过的坑 |
|---|---|---|
| 告诉应用干什么 | `ui-demo/air-gallery/air-mode.txt`：`sweep <logPath> open=<k1,k2,…>` | 没有 argv |
| 把结果拿回来 | 应用自己写 `air-trace.txt`（`START` / `OPENED n` / `PAGE id` / `ERROR …` / `SWEEP DONE n` / `END errors=n`） | `adl.exe` 是 **GUI 子系统**二进制：父进程用管道 spawn 它，窗口正常开、**流是空的**（实测） |
| 错误从哪来 | `loaderInfo.uncaughtErrorEvents`（不然 AIR 只会打印然后忘掉） | 帧守卫在 AIR 上不存在，未捕获错误会中断当前帧 |
| 往哪写 | `new File("C:/…/air-trace.txt")` | `File.applicationDirectory` 拿到的 File **只读**，写入抛 `fileWriteResource` #3003（实测） |

驱动方式刻意选「**由模型驱动的开关**」而不是伪造鼠标：`DocsAir` 在 sweep 模式下每页翻三拍
（落地 → 把所有 `m.bool("<x>.open")` 键置 `true` → 再置回），这正是文档页教读者写的那句话
（「`open: true` —— 这个布尔就是模型」）。

第一次复现（旧算法 + 弹层打开）：**13 条错误**，点名 `select` / `combobox` / `datePicker`。

## 3 修法：只数「在用」的孩子

```as3
private function fixDisplayOrder(n:UiNode, next:Vector.<UiNode>):void
{
    var slot:int = n.internalCount;
    for (var i:int = 0; i < next.length; i++)
    {
        var c:UiNode = next[i];
        c.lastIndex = i;                       // 身份 token 仍是描述下标
        if (c.backing != null && c.backing.parent == n.backing)
        {
            n.backing.setChildIndex(c.backing, slot);
            slot = slot + 1;
        }
    }
}
```

两点是刻意的：

1. **槽位只对真正的孩子前进** ⇒ `slot` 最多走到 `numChildren-1`（有 `aboveContent` 时少一），
   越界**结构性**不可能发生，而不是靠夹紧兜底。
2. **`lastIndex` 仍是描述下标**。它是未带 key 兄弟的**身份 token**（`UiNode.token`），不是显示位，
   改它会把 keyed reconcile 的判断弄坏——而这个字段被混淆过（名字就叫 `lastIndex`），注释写清。

验证：

- `node tools/air-sweep.cjs` → **41/41 页 / 10/10 弹层 / 0 runtime error**；
- AOT 侧无回归：`node tools/gates.cjs` → **42/42 PASS**（`reviews/gates-all-25.txt`），含
  `probes/widgets/{overlay,popup,flip,choice,scrollbar}` 与 41 页 tour。

## 4 门：`tools/air-sweep.cjs`（本仓第一道真跑参考运行时的门）

判据（**全部**，少一条就 FAIL）：

| 判据 | 为什么它是判据 |
|---|---|
| `START` 存在 | 应用真起来了 |
| 41 页**恰好一次、且按目录顺序** | 早死的窗口（在第 N 页崩掉）不许看起来跟通过一样 |
| `SWEEP DONE n` 且 `n == 目录页数` | 同上，且页数不写死——从 `DocsCatalog.as` 解析 |
| `OPENED k` 且 `k == 派生出的弹层键数`（现 10） | **`OPENED` 是翻完之后从模型里数出来的**。少写一步「打开」⇒ 报 0 ⇒ 门必须红。否则这道门会变瞎还说自己绿 |
| `END errors=0` 且 零 `ERROR ` 行 | 用户看到的那个东西 |

弹层键**从 demo 源码推导**（`/m\s*\.\s*bool\s*\(\s*"([^"]+\.open)"/`，注释先抹掉——`DocsAir` 的
头注释里就写着这个模式，不抹会把占位符当键），所以**新增一个可弹层不用改门**。

### 变异（`tools/mutation-air-sweep.cjs`，3/3 CAUGHT，逐字节还原）

| # | 变异 | 结果 |
|---|---|---|
| M1 | **把槽位计数改回 `internalCount + i`**（= 用户报的那个缺陷） | `6 runtime error(s)`，`[select]`/`[combobox]`/`[datePicker]` 各 `#2006`（另有几页重复计数） |
| M2 | 删掉「打开弹层」那一步 | `OPENED` 缺失 ⇒ 41 页 0 错误但**已经瞎了**，门变红 |

每个变异都按 sha256 逐字节还原，还原后重跑基线确认真的放回去了。

**它看不见什么**（写清楚，不粉饰）：只覆盖**不需要点击**就能到达的状态（页面切换 + 由模型驱动的弹层
开合）。「点 trigger 才打开」的路径在 AIR 里无法到达——那一半仍归 AOT tour 与各控件探针。这道门补的
是**反向的一半**：AOT 看不见的，让 AIR 说。

## 6 教训

1. **「我们收下了」不是证据，「AIR 收下了」才是**。同一份源码在两侧语义不同时，宽容的一侧会把缺陷
   藏起来；唯一的发现方式是**让严格的那一侧自己宣告**。
2. **画面相同 ≠ 行为相同**。夹紧到末尾恰好是正确的显示位，所以这次连像素级对照都无效——判据必须是
   **运行时报了什么错**，不是它画成什么样。
3. **门要数「效果」，不是数「步骤」**。`OPENED` 若只是「我执行过打开」的日志，删掉打开那行它照样有；
   从模型里数出来才是测量。
4. **夹具必须把「不透明失败」变成「具名失败」**：早死的窗口、没打开的弹层、写不进去的日志文件，都要
   各有一个判据，否则这道门迟早会**自称绿**。
