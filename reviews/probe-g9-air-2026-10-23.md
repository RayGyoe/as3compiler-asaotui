# 实测（真 AIR 51.4.1）：G9 是**我们的缺陷**，不是「和 AIR 对齐」

日期：2026-10-23　工作区：`asaotui/`　编译器仓库：**零改动**

## 0 为什么要重做这条判定

`compiler-gaps.md` G9 原本写「判定：**遗留欠账**」，依据是 AGENTS §1.5 的硬判据「`adl` 能跑对、
我们跑不出」。但当时本机没有 AIR SDK，这个「adl 能跑对」是**推断**，不是实测 —— 而 G9 的
整条结论恰恰寄生在这个前提上。本轮把 SDK 找出来了（在 `D:` 盘，之前的全盘搜索漏了），
于是可以直接 A/B。

## 1 结论先行

**是我们的缺陷（遗留欠账），已用真 AIR 逐值确认。**

同一份用例源 `G9Cases.as`（26 条），两条工具链：

```
AIR 51.4.1.1 : ---- 26 checks, 0 failures ----
我们的 AOT   : ---- 26 checks, 7 failures ----
```

七条失败**全部**是 `Boolean(...)` 作用在静态声明为 `Object` 的量上；同一个值的其他六种读法
（`typeof` / `String()` / `is Boolean` / `== false` / `=== false` / `Number()` / `== null` / `if`）
两臂**逐字符相同**，包括 `if (o)` 正确不进分支。

⇒ 不是「Object 槽丢了箱信息」，而是 **`Boolean()` 这一个降级入口**绕过了拆箱。

## 3 根因：一个 type-kind 分支吞了 `Object`

`src/emit.ts:32221` 的 `Boolean` 转换：

```ts
case 'Boolean': {
  if (e0!.type.kind === 'string') { ... }            // 空串为假，正确
  if (e0!.type.kind === 'bool') return e0!.code;     // 正确
  if (e0!.type.kind === 'any') return as_v_truthy;   // 正确
  if (e0!.type.kind === 'null') return false;        // 正确
  if (e0!.type.kind === 'interface') ...
  if (e0!.type.kind === 'dict' || e0!.type.kind === 'class' || this.isRefType(e0!.type))
      return `(${e0!.code} != NULL)`;                // ← Object 落到这里
  ...
}
```

上面的注释本身写着「以 AIR 实测为准：`Boolean({})` / `Boolean([])` / `Boolean(new Sprite())`
都是 `true`」—— 对**真对象**成立。漏掉的是：`Object` 这个 C 槽位在 AS3 里**还允许装标量**
（`as_value_to_obj` 会把 `Number`/`Boolean`/`String` 装箱成包装体写进去），而 AVM2 的
`Object` 槽位本来就是「原子」槽，`false` 进去还是 `false`，`Boolean()` 看到的仍是原值。

生成 C 对照（同一段代码里的四条路径）：

```c
bool _once0 = (_o != NULL);                                        // Boolean(o)      ← 错
if (as_v_truthy(as_obj_to_value((void*)(_o)))) { ... }             // if (o)          ← 对
char* _once1 = as_obj_to_str(_o);                                  // String(o)       ← 对
bool _once2 = (as_is_bool_obj(...) || ...);                        // o is Boolean    ← 对
```

`if (o)` 已经是**正确口径**，`Boolean(o)` 却没跟上 —— 这是同一语义的两处降级不一致。

## 4 修法（未实施，待定）

一处分支，与 `if` 对齐即可：

```ts
if (e0!.type.kind === 'object' && e0!.type.className === 'Object')
  return { code: `as_v_truthy(as_obj_to_value((void*)(${e0!.code})))`, type: { kind: 'bool' } };
```

**只限 `className === 'Object'`**：`Sprite*` / `Array*` 这类静态引用类型不装标量，保持
`!= NULL`（`as_obj_to_value` 会把数组重新装箱成 tag 6，虽然也对，但多一次调用没有意义）。

运行时不需要改：`as_obj_to_value`（`runtime.ts:3455`）已把四种包装体拆回原 tag，
`as_v_truthy`（`runtime.ts:1736`）对 `Number` 走 `as_num_truthy`（NaN 为假）、对 `String`
查空串、对对象查非空。

## 5 影响面

- `asaotui` 的绑定路径（`Binding.get():*` → 声明成 `Object` → `Boolean()`）是本缺陷的活路径；
  kit 里 6 处已改成 `*` 声明规避，静态钉子 `tools/find-bound-truthy.cjs` 守着不再引入。
- 任何调用方只要写 `var x:Object = ...; Boolean(x)` 就会踩到，**与 kit 无关**。
  这是库里唯一留下的「靠写法规避」的编译器缺陷，修掉后那 6 处可以改回 `Object`。

## 6 附带量到的 AS3 事实

`new Boolean(false)`：AIR 的 `typeof` 是 **`"boolean"`**，`Boolean(wrapper)` 是 **`false`**
（不是 ES3/JS 的 `"object"` / `true`）。AVM2 对 Boolean 包装器透明。我们这两格与 AIR 一致，
所以它们不是缺陷 —— 但**原先 G9 的真值矩阵没有覆盖这一格**，现在补上了。
