# 运行时主题切换（2026-10-27，第三十六轮）

> 用户要求：`Theme.setTheme(ThemeTokens.dark())` 之后**整棵树在下一帧变暗**，而**默认亮色逐字节不变**。
> 本轮把「主题」从一个 `Dirty.THEME` 常量（**零消费者**）变成一条真管线：
> **调色板 → 每 kind 基线 → 浮层 chrome → 工厂烘死的 `StyleRefinement` → 每个自绘控件的取色**。

## 1 审计先行的四条事实（改之前测到的）

| 事实 | 怎么测的 | 后果 |
|---|---|---|
| **没有任何运行时切换** | `grep setTheme kit/` = 0；`Theme` 只有 `_defaults`/`setControlDefault` | 主题是「启动时写一次」的表，不是可换的东西 |
| **`Dirty.THEME` 0 消费者** | `grep Dirty.THEME kit/` 只命中声明处 | 一个存在多年、谁也没接的脏位 |
| **134 处代码内十六进制 / 34 种颜色 / 35 文件** | `tools/hex-scan.cjs` 扫 `kit/**.as` | 调色板不是「加一个对象」就完事：每个自绘控件都是一处取色点 |
| **状态混合只有亮色语义** | `HOVER_LIFT=8` 向白、`PRESS_SINK=12` 向黑 | 暗色下「按压」比「悬停」更暗 ⇒ **按压不可见** |

## 2 五条设计决定（每条都有反例作依据）

1. **`light()` 必须逐值复现旧字面量**。探针是证据，注释不是：`probes/widgets/theme` 的亮色半场 + 既有的
   30 个控件探针（它们仍然逐个钉着亮色像素）一起作证。
2. **活调色板是私有副本**。`setTheme(t)` 把 `t` **拷入**，不别名：作者可以继续改自己那份实例，
   而屏幕上的树只跟着 epoch 走。（变异 M4 = 改回别名 ⇒ `setTheme aliased the caller's instance`。）
3. **每次 swap 必 bump `themeEpoch()`**，`UiApp` 把「epoch 变了」翻译成三件事：`markThemeDirty(主树)`、
   `markThemeDirty(浮层树)`、`invalidate(Dirty.THEME)`（= 重新 describe）。`Dirty.THEME` 从这一刻起有消费者。
4. **为多 slot 而非十二个语义 slot**。旧代码 `0xE5E7EB` 同时干四件事（面板边框 / 滑块轨道 / badge 底 /
   skeleton 条）。暗色下这四件必须能分岔，所以拆成 47 个 slot；**能晚点合并的就晚点合并**——合并能事后做，
   分不开的共享 slot 无法补救。
5. **换主题只标 `M_PAINT` + `lastStyleStale`，绝不标 layout**。调色板不动任何数字；强制重解 = 用最贵的门
   重绘，而且会让「换主题不动几何」这条判据失去意义（探针把 15 个矩形前后比对）。

## 3 四条取色通路，各自会怎么坏

| 通路 | 例子 | 坏法 | 由谁证明 |
|---|---|---|---|
| **paint-time 读** | `Theme.tokens().accent`（progress/switch/badge/…） | epoch 不 bump、或不重画 ⇒ 停在亮色 | 探针 12 个像素点在**三个相位各判一次** |
| **工厂烘死** | `table.as` 的 `headBg`、页面底色 | 只重画不重新 describe ⇒ 指针还是旧的 | 唯一能看见「describe 发生了」的点；变异 M7（`invalidate(0)`） |
| **每 kind 基线** | 按钮文字色、输入框边框 | `setTheme` 不重建 `_defaults` ⇒ 旧基线 | `btn.resolved.text.color`、`ti.resolved.borderColor`；变异 M8 |
| **浮层 chrome** | 菜单 hover 带 `OverlayChrome.ITEM_HOVER` | 静态 `StyleRefinement` 不会自己变 | 直接读静态字段；变异 M3 |

`OverlayChrome` 因此改成「几何 `const` 在前 → `_ready = boot()` → 颜色 `var` → `rebuild()`」：
几何是数字，颜色是指针，只有后者需要重建。

## 4 探针：`probes/widgets/theme`（75 checks，变异 8/8）

- **12 个采样点 × 3 个相位**（亮 → 暗（程序调用）→ 亮 → **真点击** → 暗；值手算写进 `Main.as`
  头注释与 `expect.json`）。第三个相位是**用户实际触发的那个入口**：`onClick` 里调 `setTheme`，
  也就是在事件派发**当中**重建静态 `StyleRefinement` 指针。若那不安全，症状会是错色或崩溃。
  这一段自己有牙：把处理函数指回 `light()` ⇒ 12 个点全红（`probes/widgets/theme/click-teeth.cjs`,逐字节还原）。
- **15 个矩形前后比对**：换主题**不许动几何**。
- **作者色不动**：`keep` 盒写死 `0xFF2D55`，暗色下仍是 `#FF2D55`——换主题换的是基线，不是覆盖层。
- **override 跨 swap 存活**：`setControlDefault` 现在写 `_overrides`（不是 `_defaults`），
  swap 后仍在，`clearControlDefault` 后回落到暗色基线。
- **契约**：`same`/`clone`/拷贝语义、`Theme.setTheme(null)` 抛错。

### 4.1 探针本身踩到的三件事（都是「判据写错了」）

1. **`stage.showWindow(...)` 会进入窗口的消息循环** ⇒ 写在它**之后**的模块级 `var x = [...]` 永远不会执行，
   运行期是 `null`。第一版 `#1009` 就是这个：`column(...)` 的实参是 `null` 数组。
   规矩：**所有模块级初始化都在 `showWindow` 之前**。
2. **OFF 状态的开关，旋钮就停在左边**（local x 2..18）。第一版采样点 `(20,68)` 落在旋钮白心上，
   读到的 `#FFFFFF` 与主题无关。改成 `(48,68)`（轨道右段）。
3. **1px 控件边框永远是两个半覆盖列**（实测 `#2D3644` = `#4B5563` 与 `#111827` 各 50%）。
   边框**不可能**有精确像素期望 ⇒ 输入框这条改成读 `ti.resolved.borderColor`，
   并在 `expect.json` 里写明是「删掉，不是宽恕」。

### 4.2 变异机额外发现的一件事：`markThemeDirty` 与层叠是**冗余**的

第一版探针的根节点样式在每次 `render()` 里重建（指针每次都变）。这带来一个隐蔽后果：
根节点重新解析后 `staleDescendants()` 会把整棵树标脏，于是**删掉 `markThemeDirty` 也不变红**。
实测两态：只删 `markThemeDirty` ⇒ 探针仍绿；两个都删 ⇒ 按钮文字停在亮色。
所以不是「断言没牙」，而是「这条通路在本形状下不可观测」。

修法不是加断言，是**改被测形状**：根样式与 page 样式都改成 `const`（指针稳定 ⇒ 层叠永不触发），
把调色板底色挪到一个 `position:absolute; inset:0` 的子件上（它每次 render 重建 ⇒ 唯一会动的指针，
专门用来证明 describe；又因为绝对定位不参与流，15 个矩形一个都没动）。改完后
`markThemeDirty` 成为**唯一**能把 swap 送达各节点的通路，M2 立刻被抓。

**这一条值得记住**：当两个机制互为备份时，「每个机制各写一个变异」在数学上不可能都抓到；
要么改形状让其中一个失效，要么如实说「冗余，只有一个可观测面」。

## 5 状态混合在暗色下要翻转

`PaintKit` 不再有 `HOVER_LIFT`/`PRESS_SINK` 两个常量，改成读调色板的
`hoverTint/hoverPct/pressTint/pressPct`：

| | hover | press | 为什么 |
|---|---|---|---|
| 亮色 | 向白 8% | 向黑 12% | 深色物体的「按下去」= 变暗 |
| 暗色 | 向白 8% | **向白 18%** | 暗色下变暗 = 消失；按压必须比悬停**更亮**才看得见 |

`knob` 在暗色**保持纯白**：开关/滑块/单选圆点是被照亮的实体，跟着 surface 一起变暗就没了。

## 6 数字

- 代码内十六进制：**134 → 106**（剩下的 106 里 90 在 `ThemeTokens.as` 自己身上，
  `Fill.as` 7 / `IconWidget.as` 2 / `PaintKit.as` 2 / `BoxShadow.as` 2 / `Anim.as` 1 /
  `DividerWidget.as` 1 / `TableWidget.as` 1 都是**非调色板语义**：阴影、掩码、透明命中矩形、动画常量）。
- 自绘控件改读调色板：**18 个 kind** + 5 个节点类 + 6 个工厂。
- 门 **56 → 57**；`mxmlc` 编译 **136 199 bytes / MRC_EXIT 0**；AIR 扫全站 **52/52 页 / 15/15 弹层 /
  0 runtime error**（5294 个叶子被抓、995 个真的被销毁）。
- 文档站：`theme` 页**重写**——开头就是真·明暗切换 demo（它换的是文档站自己，这是特性不是副作用），
  结尾把 `setControlDefault` 的真相写清楚（override 层、跨 swap 存活、下一次解析才生效）。

## 7 这一轮**没有**做的事

- **多语言**（3 条可见默认串 + 9 条硬编码 aria + 默认字体 `"Arial"` + 4 条语言规则 + 无 RTL）。
  审计结论留在会话记录里，越早做越便宜，但它是独立一轮。
- **文档站自己的 `DocsDemo` 配色**（`LABEL`/`TILE`/`PRIMARY`…）没纳入调色板：那是「作者配色」的
  示例入口，暗色下仍按作者色显示——正好也是第 4 节里「作者色不动」的活样本。
- 主题**持久化**（写配置/读配置）不在库里：库只管「现在是哪一套调色板」，存哪由作者决定。
