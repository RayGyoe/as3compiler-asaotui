# Shared layout differential spec -- read by BOTH drivers:
#   * yoga-driver   (C: as_ui_yg_* -> Yoga, via u1-prototype/yoga_glue)
#   * as3-driver    (pure AS3: asaot.ui.as3.As3LayoutEngine, compiled by our AOT)
#
# WHY A SHARED FILE: seam/README.md section 3.2 makes "the two engines agree" a
# HARD requirement. Two hand-written harnesses that merely assert the same
# numbers can both be right about the numbers and still disagree about the
# engine (that is exactly how the default-flex-direction bug survived cases
# a-e: they all set a direction explicitly). Driving BOTH engines from one
# frozen input and diffing their output is the only way to catch that class.
#
# FORMAT (frozen -- both drivers must parse exactly this)
#   * one directive per line; '#' starts a comment; blank lines ignored
#   * whitespace-separated tokens
#   * IDs ARE GLOBALLY UNIQUE -- a `root` line triggers calculate() immediately,
#     and checks are evaluated at end-of-file, so reusing an id would make a
#     later block's calculate overwrite an earlier check's node
#   * all lengths are POINTS unless a directive says otherwise
#   * percentages are 0..100 (the seam's convention, yoga_glue.h)
#
#   engine <web|noweb>                      set the config for nodes created from here on
#   node   <id> <parentId>                  parentId = -1 for a parentless root
#   root   <id> <availW> <availH> [ltr|rtl] decl root + calculate(); dir defaults to ltr
#   dir    <id> <row|column|row-reverse|column-reverse>
#                                           omit to leave the direction UNSET (pins the default)
#   size   <id> <w|h> <value> <point|percent>
#   minmax <id> <w|h> <min|max> <value> <point|percent>
#   pad    <id> <all|h|v|top|right|bottom|left|start|end> <value> [point|percent]
#   border <id> <all|top|right|bottom|left|start|end> <value>
#   gap    <id> <row|col|column|all> <value> [point|percent]
#   flex   <id> <grow> <shrink> <basis> <point|undefined|percent>
#   boxsizing <id> <border|content>
#   wrap   <id> <nowrap|wrap|wrap-reverse>
#   justify <id> <flex-start|center|flex-end|space-between|space-around|space-evenly>
#   align  <id> <flex-start|center|flex-end|stretch>            (align-items)
#   alignself <id> <auto|flex-start|center|flex-end|stretch>
#   aligncontent <id> <flex-start|center|flex-end|stretch|space-between|space-around>
#   margin <id> <all|h|v|top|right|bottom|left|start|end> <value> [point|percent]
#   pos    <id> <relative|absolute>
#   inset  <id> <all|h|v|top|right|bottom|left|start|end> <value> [point|percent]
#   overflow <id> <visible|hidden|scroll>
#   check  <name> <id> <l> <t> <w> <h>       expected rect, relative to the parent
#
# INCREMENTAL EXTENSION RULES (the format is frozen): every new directive above is
# ADDITIVE -- a line written for the old grammar still parses unchanged. The only
# grammar change is an OPTIONAL trailing unit token on pad/border/gap/margin/inset
# (absent == point) and an OPTIONAL trailing direction token on root (absent == ltr).
#
# Output contract for both drivers (stdout, spec order):
#   GOT <name> <l.toFixed(4)> <t> <w> <h>
#   ... then a human-readable PASS/FAIL summary and a non-zero exit on failure.
# The differential run diffs the GOT lines; the expectations inside `check` are
# only a self-test for each driver on its own.
#
# The expectation values below are the SAME hand-computed rectangles as
# u1-prototype/check-layout.md section 3 (EPS = 0.01). Do not "fix" a value to
# make a driver pass: a mismatch means an engine disagrees, which is the finding.
